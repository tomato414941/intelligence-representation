# Shogi Generated Experience Retention Policy

Status: open
Priority: medium

## Problem

Online replay and self-play generation currently write generated shogi game
records under `runs/`.

During a run, those records are useful:

- `iteration-*/generated-games.jsonl`
- `iteration-*/generated-train-games.jsonl`
- `experience-store/games.jsonl`

However, `runs/` is disposable by project policy. That means generated records
are not yet durable learning assets, even if a later checkpoint proves useful.

This is especially important for online replay. If a checkpoint improves, the
records generated by that checkpoint may be valuable future training material,
but today there is no explicit promotion or retention rule for them.

## Desired Shape

Generated experience should have a clear lifecycle:

- temporary run artifact while the experiment is running
- eligible for retention only when its generating checkpoint and settings are
  explainable
- promoted to a durable location only by an explicit decision
- safe to delete with `runs/` if it was not promoted

The durable form should preserve enough metadata to explain later reuse:

- generating checkpoint identity
- player/move selector settings
- search settings
- side assignment policy
- generation date or run identity
- source run path for traceability, without making `runs/` the source of truth

This issue should not force all generated games to be kept. Keeping everything
would make the artifact policy vague and expensive.

## Close Condition

- The project defines where promoted generated shogi experience belongs.
- Online replay records can be either explicitly promoted or safely discarded.
- Training data selections can refer to promoted generated experience without
  depending on disposable `runs/` paths.
